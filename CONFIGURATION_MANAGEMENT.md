# Правила управления конфигурацией (config-control)

Учебная основа — принципы ISO/IEC/IEEE 828 (редакция 2012, Inactive-Reserved). Полное соответствие стандарту не заявляется.

## 1. Идентификация конфигурационных единиц
Конфигурационная единица (CI) — любой файл проекта, кроме исключённых (`.git`, `__pycache__`, `venv`, `.venv`, кэши и пользовательские `--exclude`). Идентификатор CI — относительный POSIX-путь; версия фиксируется SHA-256 и размером.

## 2. Утверждение baseline
- Baseline получает уникальный ID (`BL-0001`, `BL-0002`…), дату, утверждающее лицо, Git commit hash (если проект в Git) и перечень CI с SHA-256.
- Файл baseline защищён: записывается с правами «только чтение», содержит контрольную сумму (`seal`); при нарушении целостности загрузка отклоняется.
- Изменять утверждённую baseline напрямую запрещено. Новое состояние фиксируется новой baseline со ссылкой `previous` на предыдущую.

## 3. Регистрация изменений
Любое расхождение, найденное проверкой (`added / removed / modified`), должно быть либо отменено, либо оформлено запросом на изменение и закреплено новой baseline.

## 4. Аудит
`cfgctl check` сравнивает рабочие файлы с baseline, формирует `report.json` (несоответствия) и добавляет запись в `history.jsonl` (история проверок). Код возврата 0 — соответствует, 1 — есть расхождения, 2 — ошибка (нет/повреждена baseline).

## Ограничения
Инструмент не проверяет права доступа и метаданные файлов, не аутентифицирует утверждающее лицо и не защищает от злонамеренного пересоздания baseline.
