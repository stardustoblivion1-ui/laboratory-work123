# Подтверждение сценариев GitHub Actions

Локально проверено (`relman check-tag`, код возврата 0 / 1) — те же команды выполняет `release.yml`.
Реальные запуски GitHub Actions появятся после публикации репозитория; ссылки/скриншоты вставьте в таблицу.

| № | Сценарий | Как воспроизвести | Ожидаемый результат | Ссылка / скриншот |
|---|---|---|---|---|
| 1 | Успешная релизная сборка | `git push origin main && git push origin v1.0.0` (версия в pyproject = 1.0.0) | ✅ Release build; в Artifacts есть `dist` (wheel + sdist) | _вставить_ |
| 2 | Тег не совпадает с версией | `git tag v1.0.1 && git push origin v1.0.1` | ❌ шаг «Verify tag…»: *Тег v1.0.1 не соответствует версии пакета 1.0.0*; артефактов нет | _вставить_ |
| 3 | Некорректный формат тега | `git tag v1.0 && git push origin v1.0` | ❌ *Некорректный формат тега 'v1.0'* | _вставить_ |
| 4 | push / pull_request | обычный коммит в ветку или PR | ✅ только `pytest`, проверка тега не выполняется (`ci.yml`) | _вставить_ |

Примечание: тег `v1.0.1` из сценария 2 после проверки удалите: `git push --delete origin v1.0.1 && git tag -d v1.0.1`.
