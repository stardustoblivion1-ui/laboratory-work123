# Практики управления конфигурацией: что поддерживается, а что нет

| Практика (по мотивам ISO/IEC/IEEE 828) | Статус | Комментарий |
|---|---|---|
| Идентификация: наличие README, CHANGELOG, pyproject | ✅ поддерживается | список файлов настраивается в `rules.json` |
| Контроль версий (Git-репозиторий, число коммитов) | ✅ поддерживается | минимальное число коммитов настраивается |
| Формат версии MAJOR.MINOR.PATCH | ✅ поддерживается | читается из `[project].version` |
| Наличие CI workflow | ✅ частично | проверяется только наличие `*.yml`, не их содержание и не результаты запусков |
| Отчётность с уровнем критичности | ✅ поддерживается | JSON и HTML |
| Baseline и сравнение с ней | ❌ не поддерживается | см. проект `config-control` |
| Одобрение изменений, трассируемость запрос → коммит | ❌ не поддерживается | см. `scm-traceability` |
| Проверка прав доступа, подписей коммитов, ролей | ❌ не поддерживается | |
| Аудит содержимого CHANGELOG и качества тестов | ❌ не поддерживается | |

Результаты аудита **не являются сертификацией** и не подтверждают соответствие ISO/IEC/IEEE 828.
